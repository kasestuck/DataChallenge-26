# CQA Insight

**AI-система оценки качества клиентских диалогов**

Freedom Broker CQA Hackathon 2026 · команда **TheGoldenDuo**

CQA Insight выполняет первичную проверку работы оператора по настраиваемому чек-листу. Система принимает чаты и транскрипты звонков, получает от AI ответы по критериям и обоснования, проверяет ссылки на реплики и рассчитывает баллы отдельным кодом. Проверяющий может открыть доказательство, оспорить критерий и сохранить решение с пересчётом итога. Исходная оценка при этом сохраняется.

Это локальный прототип с внешним AI API. Демонстрационный режим интерфейса и работа с настоящим бэкендом разделены; демонстрационный вход не является системой контроля доступа.

## Ценность для бизнеса

Система помогает направить ручную проверку на спорные оценки, нарушения и неполные ответы, применяет единые критерии и сохраняет доказательства решения. Версии чек-листа позволяют проследить, по каким правилам получен результат; апелляции поддерживают работу проверяющего и сохраняют историю пересмотра.

Это может уменьшить объём первичного ручного просмотра, но экономия времени, денег и изменение качества обслуживания пока не измерены. Повторяемость модели не заменяет человеческую экспертизу: особенно важны контекст запроса, N/A, конфиденциальность и неоднозначные формулировки шкал. Массовая обработка реализована с ограниченной параллельностью; масштабирование на несколько серверов потребует отдельной архитектуры очереди и хранения.

## Основные возможности

- Импорт набора организаторов через бэкенд либо локального JSON; ручная загрузка транскрипта через API и интерфейс. Исходные ID, роли и метки времени сохраняются.
- AI-оценка только действий оператора. Реплики клиента, бота и системы используются как контекст и возможные доказательства. Аудио не распознаётся: анализируется готовый транскрипт.
- Восемь исходных критериев, ответы N/A, точные ступени шкал, нормированные итог и оценки секций, отдельный флаг грубого нарушения.
- Обоснование, цитата и `message_id`; переход из результата к подсвеченной реплике. Для звонка показывается аудиоплеер при наличии URL, но evidence не перематывает его.
- Редактор чек-листа: формулировки, типы, веса, условия N/A, ступени с описаниями; каждое сохранение создаёт неизменяемую версию. Внутренний расчёт поддерживает новые критерии, официальный экспорт ограничен исходными восемью.
- Полная и частичная переоценка, API batch с прогрессом. Изменение только веса может потребовать лишь пересчёта; при отсутствии подходящей предыдущей оценки выполняется полный запрос модели.
- Апелляция по критерию, комментарий, фрагмент транскрипта, ручное подтверждение/изменение с причиной; исходный и финальный результаты хранятся отдельно. AI-рекомендация сама не принимает решение.
- Overview по текущему снимку БД: статусы, среднее, медиана, распределение, языки, каналы, апелляции, usage. Временной тренд и сравнение периодов не вычисляются.
- Интерфейс RU/KK/EN, экспорт результатов JSON, учёт физических вызовов модели, токенов и известных тарифов.

**Операторы:** в исходных данных нет стабильного `operator_id`. Профили и статистика по операторам доступны только на вымышленных данных Demo Mode; Real API Mode прямо сообщает об ограничении и не выводит идентичность из имени в реплике.

## Архитектура

```text
API организаторов / JSON-файл / ручная загрузка
                         |
                         v
Frontend <--------> FastAPI <--------> SQLite
                         |
                версия чек-листа + транскрипт
                         |
                         v
                   Meta AI API
                         |
                ответы + доказательства
                         |
                         v
             Validation -> Decimal scoring
                         |
                         v
                 SQLite -> Frontend
                         |
          апелляция -> явное решение -> пересчёт
                         |
                         v
              экспорт JSON -> независимый валидатор
```

Один процесс Uvicorn обслуживает API и разрешённые файлы интерфейса. Блокирующие оценки batch выполняются вне event loop; `asyncio.Semaphore` ограничивает параллельность. SQLite хранит диалоги, сообщения, версии, оценки, критерии, апелляции, решения, журнал LLM и задачи. При старте зависшие задачи помечаются `interrupted`, а неизвестный платный вызов автоматически не повторяется.

Нужны Git и Python 3.11+; проверенная среда использовала Python 3.12.14. Команды ниже — PowerShell, из корня проекта. Git clone и чистая установка зависимостей в этой проверке не повторялись: проверены установленное окружение, `pip check`, CLI и запуск приложения.

```powershell
cd DataChallenge-26
```

Существующий `.env` команда не перезаписывает. Вставьте **собственный ключ** только в локальный `.env`; не вводите его в браузер и не добавляйте в Git.

```dotenv

META_MODEL=muse-spark-1.3
DATABASE_PATH=data/cqa.db
```

### Demo Mode и Real API Mode

1. Нажмите «Начать работу», выполните демонстрационный вход с непустыми e-mail и паролем. Пароль не проверяется; это не аутентификация.

Режим сохраняется в `localStorage`; `localhost` и `127.0.0.1` имеют разные хранилища. Если ранее задан адрес через `window.CQA_API_BASE` или `localStorage['cqa-api-base']`, он имеет приоритет. Для раздельных адресов настройте `CORS_ORIGINS`.

## Процесс AI-оценивания

1. Из БД читаются транскрипт и выбранная неизменяемая версия чек-листа. Каждая реплика имеет `m1`, `m2` и далее по исходному массиву; строки времени не переписываются.
2. Код формирует запрос с активными критериями, языком, каналом и транскриптом. Текст диалога обрамляется как данные; команды внутри него игнорируются по системной инструкции.
3. Meta API возвращает сырые ответы, объяснения, evidence и проверенные диапазоны. Модель не рассчитывает итог.
4. Проверяются JSON, покрытие критериев, допустимые значения, N/A, существование реплик и принадлежность цитат. При ошибке возможен один запрос исправления.
5. Чистая функция на `Decimal` рассчитывает баллы, секции и эффективные веса.
6. Сохраняются снимок диалога, версия чек-листа, SHA-256 системного промпта, исходный ответ, результат проверки, токены и известная стоимость. История позволяет открыть прежнюю оценку.
7. Человек может создать апелляцию, получить AI-подсказку через API и отдельно принять решение. Исходный результат не перезаписывается.

Официальный чек-лист и типы **экспортируемых** значений:

| Внутренний ID | criterion_id в results.json | Вес | value |
| --- | --- | ---: | --- |
| 01 | contact | 10 | `true`, `false` |
| 02 | discovery | 15 | `true`, `false`, `null` |
| 03 | identification | 20 | `true`, `false`, `null` |
| 04 | consultation | 20 | `0`, `5`, `10`, `15`, `20`, `null` |
| 05 | empathy | 15 | `true`, `false` |
| 06 | dialogue | 15 | `0`, `4`, `7`, `10` |
| 07 | closure | 5 | `true`, `false`, `null` |
| 08 | critical | — | `true`, `false`; отдельный флаг |

Во внутреннем API ответы представлены строками `yes/no/na` либо ключом шкалы. N/A разрешён только при выполненном условии критерия и исключает его вес из знаменателя.

```text
yes: earned = weight; no: earned = 0
scale: earned = weight × value / max(scale)
final_score = round(sum(earned) / sum(applicable_weights) × 100, 2)
```

Например, `dialogue=7` даёт `15 × 7/10 = 10,5` до нормирования. Верхняя ступень шкалы определяется конфигом. При отсутствии применимых положительных весов итог `null`. Округление — `ROUND_HALF_UP`, до двух знаков. `critical_flag` передаётся отдельно и **не обнуляет итог автоматически**.

Произвольные внутренние чек-листы могут иметь другую сумму весов. Для сдачи экспортёр требует исходные восемь ID, веса, типы, N/A и шкалы; несовместимую версию он отклоняет.

## Надёжность и валидация

- Неполный/невалидный ответ после одного исправления получает `needs_review`; валидные критерии сохраняются, общий итог недоступен. Ошибка провайдера сохраняется как `failed`, без выдуманного результата.
- Проверка цитаты подтверждает наличие текста в нужной реплике. Она **не доказывает**, что модель правильно истолковала смысл.
- Для `no` и любой ступени ниже максимума требуется диапазон проверки; для N/A — обоснование с условием применимости. Реплики всех ролей могут служить доказательством, но оценивается оператор.
- 401/403/404 не повторяются; 429 допускает до четырёх попыток с `Retry-After`, 5xx/таймауты — до трёх. Обрезанный ответ не принимается за готовый.
- Сетевой/upload лимит по умолчанию — 20 MiB; LLM-вход — 100 000 символов, выход — 8192 токена, таймаут — 120 с. Транскрипт не обрезается молча. Отсутствие реплик оператора выявляется до модели.
- Batch изолирует ошибки отдельных диалогов и пропускает готовую оценку той же версии и редакции транскрипта, если не задан `force`.

**Техническая валидность и повторяемость не являются точностью относительно экспертов.** Согласованный Ground Truth и независимая проверка точности для текущей версии не опубликованы.

### Формат и проверка результатов

Структура сверена с предоставленным организаторами **CQA_Student_Guide_Appendix_Results.pdf**, страницы 1–3; локальная копия PDF не включена в репозиторий.

- `value` — булево, целая ступень или разрешённый `null`; `rationale` непустой, `evidence_turns` указывает позиции от 1 в полном исходном `transcript`, включая client, operator, bot и system.

## Безопасность и ограничения

- Ключ хранится в серверном `.env`; [.gitignore](.gitignore) исключает `.env`, `.venv/`, `data/`, БД и кэши. [.env.example](.env.example) не содержит ключа. Изменённые документы проверяются на секреты; это не утверждение о полном независимом аудите всей Git-истории.
- Demo Auth сохраняет флаг входа и e-mail в `sessionStorage`, очищает поле пароля и не проверяет его. Настоящая авторизация и разграничение доступа не реализованы. CORS `*` предназначен для локальной разработки.
- В основных UI-компонентах пользовательские строки экранируются; локализация использует `textContent`. Это снижает риск XSS, но не заменяет отдельный аудит безопасности.
- Транскрипты передаются внешнему AI-провайдеру; в SQLite сохраняются исходные тексты, ответы и доказательства. Полная анонимизация, шифрование SQLite и политика хранения данных не реализованы; доступ и условия передачи должен обеспечить владелец системы.
- Отсутствие данных не заменяется фактом, нулевым счётом или известной стоимостью. Проверка цитаты не гарантирует верность рекомендации или экспертной трактовки.
- UI не использует API batch/jobs, частичную переоценку и AI-подсказки апелляций. Списки сортируются и пагинируются клиентом; сравнения версий рядом нет, история доступна в карточке.
- Аудио не анализируется; нестандартные метки времени сохраняются, некорректный offset может быть `null`.
- Это прототип, а не подтверждённая production-ready система. Нагрузочное тестирование, развёртывание на нескольких процессах, полный повтор браузерного E2E и независимая экспертная оценка текущего промпта остаются открытыми задачами.
