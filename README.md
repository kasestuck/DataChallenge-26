# CQA Insight — TheGoldenDuo

Система оценки качества клиентских диалогов для Freedom Broker CQA Hackathon.
FastAPI и SQLite хранят диалоги, версии чек-листов, оценки с доказательствами и апелляции.
Интерфейс на HTML/CSS/ES modules работает без сборки. Языки диалогов: RU, KZ, EN.

## Установка

Python 3.11+. Из корня проекта в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

Существующий `.env` сохраняется. Для реальной оценки заполните в нём `MODEL_API_KEY`,
`META_BASE_URL` и `META_MODEL`; для загрузки набора по сети — `DATASET_API_URL` и
`DATASET_GROUP_ID`. Ключ хранится только на бэкенде. Проверка здоровья, импорт из файла,
расчёт баллов и тесты не требуют ключа модели. Зависимости закреплены точными версиями.

## Единый запуск

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8001
```

Откройте [интерфейс](http://127.0.0.1:8001/),
[Swagger](http://127.0.0.1:8001/docs) или
[проверку здоровья](http://127.0.0.1:8001/api/health).
Один процесс обслуживает REST API и интерфейс: корневой `index.html` и каталоги
`/assets`, `/css`, `/js`, `/src`. Остальные файлы репозитория через эту раздачу недоступны.
Если присутствует прежний каталог `frontend/`, используется он. Не запускайте
`http.server` из корня объединённого проекта с `.env` и базой данных.

## Реальные данные в интерфейсе

1. Нажмите «Начать работу» и выполните демонстрационный вход: непустые e-mail и пароль.
   Это Demo Auth, без проверки пароля и без контроля доступа.
2. В шапке Workspace переключите **«Демо» → «API»** и откройте раздел «Диалоги».
   «Демо» содержит вымышленные данные; режим «API» обращается к бэкенду и показывает
   ошибки без подмены результатами демо.
3. API по умолчанию находится на том же origin, что и страница: `/api`.
   Для единого запуска дополнительные настройки браузера и команды в консоли не нужны.

Выбранный режим сохраняется для текущего origin; `localhost` и `127.0.0.1` имеют
разные хранилища. Ключ модели в браузер вводить не требуется. Явно заданный ранее
адрес API имеет приоритет над значением по умолчанию. При раздельном размещении
интерфейса и API разрешённые origins задаются через `CORS_ORIGINS` на бэкенде.

## Возможности режима API

- Overview показывает текущий снимок БД: число диалогов и статусы оценок, среднее,
  медиану, распределение баллов, грубые нарушения, открытые апелляции, языки и каналы.
  Токены и стоимость берутся из журнала вызовов; без цен выводится «цена не задана».
  Временной тренд и изменение за период не выдумываются.
- Импорт принимает массив диалогов, объект `{"records":[...]}` и прежний формат
  `{"conversations":[...]}` с `messages`. Сохраняются ID, произвольный канал и исходные
  метки времени; каждая запись получает результат приёма или причину отказа.
- Загруженные вручную диалоги относятся к `UPLOAD`. Импорт с ID существующего DEV
  отклоняется с `409 UPLOAD_ID_CONFLICT`. Источник доступен в API через
  `dataset_group_id`; массовый `all:true` без фильтра исключает `UPLOAD`.
- Диалоги и оценки показывают реплики с `message_id`, evidence, N/A, ошибки валидации,
  итог и историю. Апелляции сохраняют исходную оценку и отдельно показывают решение.
- Редактор чек-листа создаёт неизменяемую новую версию, позволяет менять `yes_text`,
  `no_text` и точные ступени шкалы с описаниями. Сумма весов не обязана быть 100:
  бэкенд нормирует результат сам.
- Раздел «Операторы» объясняет отсутствие стабильного `operator_id` в исходных
  данных. Статистика и привязка оператора не строятся по именам из текста.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node tests/contract_adapter_node.mjs
.\.venv\Scripts\python.exe scripts/list_models.py
.\.venv\Scripts\python.exe scripts/smoke_test.py
```

`pytest` использует тестовые модели; Node-проверки адаптера используют синтетические
ответы HTTP и не вызывают сеть или модель. Две диагностические команды обращаются к
провайдеру и требуют заполненного ключа. При пустом ключе диагностика должна
сообщить ошибку конфигурации. Успешный smoke test проверяет доступ к модели,
а качество оценок проверяется отдельно.

## Текущие ограничения интерфейса

- Переоценка из UI выполняет последовательные полные запросы. Batch, прогресс задач,
  частичная переоценка `criterion_ids` и AI-подсказка апелляции доступны через API,
  но пока не подключены к кнопкам интерфейса.
- Список оценок строится из последних результатов диалогов; пагинация и сортировка
  клиентские. Неизвестная дата создания оценки не подменяется временем загрузки диалога.
  Фильтр версии и сортировка по дате скрыты; история и метаданные доступны в карточке.
- Overview охватывает всю текущую БД. Среднее и медиана используют завершённые,
  неустаревшие оценки с известным итогом; стоимость включает всю историю вызовов.
- Назначение оператора недоступно без стабильных идентификаторов в данных.
- Демонстрационный вход не защищает API. Проект предназначен для локального прототипа.
