# Тестирование Frontend

Интерфейс использует ES modules без сборки. Браузерные тесты работают в видимой
вкладке: фоновые вкладки могут замедлять таймеры и iframe. Итог записывается в
`document.title` и `window.__SMOKE__`, `window.__ADAPTERS__` или `window.__E2E__`.
Node нужен только для отдельного теста адаптера, не для запуска приложения.

## Проверки без сервера и модели

Из корня проекта:

```powershell
node tests/contract_adapter_node.mjs
.\.venv\Scripts\python.exe -m pytest -q
```

Node-проверки используют только синтетические HTTP-ответы внутри теста: same-origin,
импорт организаторского/старого формата, частичные отказы, конфликт источников,
Overview, ошибки без mock-fallback, фильтры, шкалы, исходные/финальные оценки и
список более 100 апелляций. Они не вызывают сеть, модель и не записывают БД.
`pytest` использует тестовые БД и подмену LLM только в тестах.

В текущем изменении подтверждены: `contract_adapter_node.mjs` — **10/10 PASS**;
существующий `tests/adapters.js` — **47/47 PASS под Node с DOM shim**.
Второй результат проверяет логику harness, не является браузерной проверкой.

## Изолированная статика для браузерных тестов

Основной сервер намеренно не раздаёт каталог `tests/`. Скопируйте только разрешённые
UI-файлы и шесть файлов браузерных тестов в новую временную папку. `.env`, БД,
`data/`, результаты сдачи и Python-код в эту копию не попадают.

PowerShell, из корня проекта:

```powershell
$cqaUiTestRoot = Join-Path ([System.IO.Path]::GetTempPath()) ('cqa-ui-tests-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $cqaUiTestRoot | Out-Null
Copy-Item -LiteralPath @('index.html', 'assets', 'css', 'js', 'src') -Destination $cqaUiTestRoot -Recurse
$cqaUiTests = Join-Path $cqaUiTestRoot 'tests'
New-Item -ItemType Directory -Path $cqaUiTests | Out-Null
Copy-Item -LiteralPath @('tests/smoke.html', 'tests/smoke.js', 'tests/adapters.html', 'tests/adapters.js', 'tests/e2e.html', 'tests/e2e.js') -Destination $cqaUiTests
.\.venv\Scripts\python.exe -m http.server 5180 --bind 127.0.0.1 --directory $cqaUiTestRoot
```

Раздаётся только `$cqaUiTestRoot`, а не текущая папка репозитория.
Откройте нужную страницу:

| Страница | Проверка |
|---|---|
| `http://127.0.0.1:5180/tests/smoke.html` | Demo-данные, UI-компоненты, i18n, маршруты, ширины экрана, обработка ошибок |
| `http://127.0.0.1:5180/tests/adapters.html` | Мапперы реального адаптера, HTTP-клиент, фасад режимов |
| `http://127.0.0.1:5180/tests/e2e.html` | Сценарии интерфейса в Demo Mode |

Скопированная статика — снимок: после изменений исходников создайте новую копию.
Для проверки именно действующего приложения используйте единый запуск из README,
а не временную статику.

## Live-тест адаптера: только отдельная БД

Live-harness создаёт диалоги `fe-live-*` и версии чек-листа. Не направляйте его на
основную БД. В отдельном окне PowerShell из корня проекта:

```powershell
$env:DATABASE_PATH = Join-Path ([System.IO.Path]::GetTempPath()) ('cqa-api-tests-' + [guid]::NewGuid().ToString('N') + '.db')
$env:CORS_ORIGINS = 'http://127.0.0.1:5180'
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8002
```

Затем откройте:
`http://127.0.0.1:5180/tests/adapters.html?live=1&api_base=http%3A%2F%2F127.0.0.1%3A8002%2Fapi`.
Параметр `api_base` поддерживает именно тестовая страница. Без него live-harness
использует `/api` на origin тестовой страницы. Проверяются health, импорт, фильтры,
деталь, версии чек-листа и ошибки; настоящая оценка моделью не запускается.

## Проверка сценариев режима API

Для каждого сценария фиксируйте источник, ожидаемый результат и фактический ответ.
Создание данных и версий выполняйте только в отдельной БД.

1. Demo Auth → переключатель API → Overview: реальные счётчики, языки/каналы,
   отсутствие выдуманного тренда, неизвестная стоимость без подстановки нуля.
2. Импорт массива и `records`, произвольный канал, пропущенное время, ошибочная запись
   между корректными. Результат по каждой строке; DEV при совпадении ID не меняется.
3. Диалог → оценка → evidence: `message_id`, N/A, невалидный ответ, итог и usage.
4. Апелляция → допустимый ответ → решение: исходный снимок сохранён, финальные баллы
   согласованы с финальным ответом; повторное решение отклонено.
5. Чек-лист: вес больше 100, сумма не 100, sparse-шкала и описания, yes/no, новая версия.
6. Остановленный/недоступный API: видимая ошибка, без перехода на демонстрационные данные.

Новый вызов модели — отдельная проверка с ключом и расходом токенов. Просмотр уже
существующей оценки не доказывает, что такой вызов выполнен в текущем прогоне.

## Ограничения подтверждения

Node-тесты не подтверждают внешний вид, кросс-браузерность и доступность для
скринридеров. Прогон с синтетическими ответами не измеряет точность AI. Наличие
готовых результатов в БД не заменяет отдельной проверки новых запросов модели.
Текущие браузерные результаты фиксируются в отчёте после фактического завершения.
