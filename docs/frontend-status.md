## Исправлено в Stage 4

* API-слой разделён: `config.js`, `http.js`, `mockAdapter.js`, `realApiAdapter.js`, фасад `api.js`. Режим API больше не использует выдуманный `/api/v1` и формат ответов.
* В режиме API оценка, пришедшая синхронно, обновляет статус и итог диалога из Backend (раньше мок всегда возвращал `running`, и статус «Оценивается» мог остаться навсегда).
* Дата «1 янв.» и время `05:00:00` для данных без `timestamp` заменены на «—»/скрыты (не показываем выдуманные даты).
* Статус `needs_review`, ошибки 502/429/504 модели, вид `unsupported`, `ApiError.code`.
* Форма решения апелляции в API принимает новый **ответ** по критерию (yes/no или ключ шкалы), как требует Backend.

## Известные ограничения / что не сделано

* Нет проверки на реальных ответах модели (оценки, апелляции, `needs_review`, частичная переоценка `criterion_ids`, batch/jobs не используются).
* Нет сравнения результатов двух версий чек-листа «рядом» (доступна история оценок диалога и переоценка).
* Не реализована активация старой версии чек-листа в UI (адаптер `activateChecklist` есть).
* AI-подсказка по апелляции (`/appeals/{id}/ai-suggest`) в UI не подключена.
* Верхний поиск Workspace отключён (`disabled`) — у каждого списка свой поиск.
* Playwright не добавлялся: тесты — браузерные страницы без сборки; автоматического запуска из CI нет (нет Node в окружении).
* Измерений производительности (FPS/время рендера) не проводилось; измерено только отсутствие роста DOM при 120 переходах между разделами (1009 → 1009 элементов).
