# Интеграция Frontend с Backend

Текущая связка использует один FastAPI-процесс: API под `/api` и разрешённую статику
интерфейса на `/`. Адаптер `js/realApiAdapter.js` переводит REST-контракт во внутреннюю
модель экранов. Режим API не подменяет ошибки демонстрационными результатами.

## Запуск и вход

Установка и единственная команда запуска проекта приведены в [README](../README.md#единый-запуск).
Откройте `http://127.0.0.1:8001/`, нажмите «Начать работу», выполните Demo Auth
(непустые e-mail и пароль), затем в шапке Workspace выберите **API**.
API автоматически использует origin открытой страницы и путь `/api`: команды в
консоли или настройка localStorage для обычного запуска не нужны.

Явные настройки `window.CQA_API_BASE` / `cqa-api-base` сохраняют приоритет над
значением по умолчанию для раздельного размещения. `CORS_ORIGINS` на бэкенде должен
разрешать origin такого интерфейса. `MODEL_API_KEY`, модель и цены задаются только
на бэкенде. Не запускайте несколько workers: очередь задач прототипа находится в процессе.

## Соответствие экранов API

| Экран / действие | Реальный источник и поведение |
|---|---|
| Overview | Параллельно `GET /api/conversations`, `/api/appeals`, `/api/stats/cost`; агрегаты вычисляются из полученного снимка, без отдельного `/overview` |
| Диалоги | Список, серверные фильтры, деталь и история; `message_id` и исходные строки времени сохраняются |
| Импорт | Последовательные `POST /api/conversations/upload`; успешные и отклонённые записи показаны отдельно |
| Оценки | Список последних оценок выводится из списка диалогов; полная карточка — `GET /api/evaluations/{id}` |
| Запуск оценки | `POST /api/evaluations`, синхронный ответ; UI ждёт до 180 секунд и показывает ошибку модели при отказе |
| Апелляции | Создание, список, карточка, решение `confirm/change`; итог пересчитывает бэкенд |
| Чек-листы | Версии, активная версия, создание новой версии; явные формулировки yes/no и словарь ступеней шкалы |
| Операторы | Сообщение об отсутствии стабильных идентификаторов; запросы к несуществующему `/operators` не нужны |

Статус фактических проверок и исторические прогоны перечислены отдельно в
[testing.md](testing.md). Реализация операции по контракту не означает, что в текущем
прогоне заново вызывалась модель.

## Импорт и источники

Форматы файла: массив записей, `{"records":[...]}` или прежний
`{"conversations":[...]}`. Запись организаторов содержит `conversation_id`, `language`
(`RU/KZ/EN`), произвольную строку `channel`, `transcript` с `speaker/text/timestamp`
и необязательный `audio_url`. Старые записи с `messages[].role` также поддерживаются.

Импорт сохраняет ID и канал, не удаляет невалидные реплики ради успешного приёма.
Запись с ошибкой отклоняется целиком, затем обрабатывается следующая. Пропущенные
метки времени не генерируются; бэкенд хранит пропуск/null пустой строкой. Нумерация
`m1`, `m2`, ... включает system и bot.

Каждый ответ содержит `imported`, `skipped` и `results[]` с индексом, ID, статусом
`accepted/rejected`, а для отказа — кодом и сообщением. `errors[]` содержит все отказы.
В интерфейсе номера строк начинаются с 1, индекс адаптера — с 0.

Загрузка через UI всегда создаёт источник `UPLOAD`. Повторный импорт может обновить
существующую запись `UPLOAD`; совпадение ID с DEV или другим источником возвращает
`409 UPLOAD_ID_CONFLICT` и ничего в этой записи не меняет. Поле `dataset_group_id`
доступно в списке/детали и как фильтр `GET /api/conversations`.

Для batch `all:true` без фильтра исключает `UPLOAD`. Явный
`dataset_group_id:"UPLOAD"` с `all:true` или явный список `conversation_ids` включает
выбранные загрузки. Одновременные `conversation_ids` и `dataset_group_id` отклоняются
с 422, чтобы фильтр не игнорировался молча.

## Семантика показателей и решений

- Overview показывает текущую БД целиком. Среднее/медиана/распределение используют
  только завершённые неустаревшие оценки с известным числовым итогом. Число завершённых
  оценок отдельно от числа итогов, включённых в расчёт. Языки/каналы охватывают все записи.
- Флаг грубого нарушения берётся из последних неустаревших результатов. Открытые
  апелляции считаются по `status:open`. Тренд, изменение за период и неизвестные даты
  не генерируются; периодные кнопки скрыты в API-режиме.
- Стоимость и токены — вся история `llm_calls`, включая повторы и апелляции.
  Неизвестная цена остаётся `null` с пояснением «цена не задана», а не нулём.
- Баллы каждой оценки приходят с бэкенда. После решения карточка критерия согласованно
  показывает финальные ответ, баллы и причину; исходные ответ и баллы хранятся отдельно.
  Апелляция использует снимок оспариваемого результата, оба итога сохраняются.
- N/A можно выбрать только у допускающего его критерия; flag не допускает N/A.
  Невалидный или неизвестный ответ не отображается как «Нет».
- Шкала чек-листа — точный словарь ступеней с описаниями. Промежуточные ступени не
  генерируются. Неактивные критерии и их настройки сохраняются при редактировании.
  Неотрицательные веса допускают сумму, отличную от 100; нормирование делает бэкенд.

## Оставшиеся ограничения

- Batch с прогрессом, частичная переоценка `criterion_ids`, загрузка набора по URL и
  AI-подсказка апелляции доступны через API/Swagger; отдельные кнопки не подключены.
  Переоценка из UI выполняет последовательные полные запросы.
- Пагинация и сортировка клиентские. Страница оценок показывает только последние
  результаты диалогов; дата оценки в таком списке неизвестна и не заменяется `updated_at`.
  Недоступные фильтр версии, колонки версии/даты и сортировка по дате скрыты.
  История, версия и дата оценки доступны в карточках.
- Нет достоверной связи диалог–оператор; имена из текста не становятся идентификаторами.
- Отдельного поля заметки к версии чек-листа нет в API; его ввод скрыт в режиме API.
- Demo Auth не проверяет пароль и не защищает API; это локальный прототип, не система
  разграничения доступа.

## Безопасность и границы проверки

Ключ модели остаётся в `.env` на бэкенде. Интерфейс не получает ключ и не отправляет
его в браузерные запросы. Тексты, evidence, комментарии и сообщения ошибок экранируются
перед отображением. Для тестовой статики используйте изолированную копию по
[инструкции](testing.md), не раздавайте корень репозитория.

Средний балл, распределение и повторяемость не являются точностью AI относительно
Ground Truth. Для оценки точности нужен отдельно зафиксированный экспертный эталон.
